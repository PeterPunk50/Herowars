## 2. Script layout

The place builds the arena and the characters at runtime. These are the only scripts in it.

|---|---|---|---:|---|

| `MeshCostumes__R4_MeshCostumes.luau` | ReplicatedStorage/HeroWars/MeshCostumes | ModuleScript | 91 | Mesh armour pieces |

How the code is put together:

- **`Rules__3.luau` is layered.** Later builds append overrides at the bottom, for example `Rules.Characters.Bulwark.Health = 135` near the end. **The last assignment wins.**
  - Read a value by evaluating it with `Rules.heroMove(hero, name)`, not by trusting the first table you see.
  - `Rules.heroMove` caches its merged tables. Any what-if test has to edit the objects it returns.
- **The client is one huge main chunk.** It sits at Luau's **200-local limit**, so put all new client code in its own `;(function() ... end)()` block (see section 5).
- **Shared tables:**
  - Client code shares state through the `Sig` table, for example `Sig.binds`, `Sig.walkFacing`, `Sig.attackId`, `Sig.touchSpot`, `Sig.onInput` and `Sig.strafe`.
  - Main tracks duels in its `D` table.
- **One remote:** `ReplicatedStorage.HeroWars.Combat`.
  - The client sends `(action, data, seq)`.
  - Main whitelists actions in `validActions`. R66 added `Coach`, `Progress` and `SaveProgress`.
- **DataStores:**
  - `HeroWarsKeybinds` holds the keybinds.
  - `HeroWarsProgress` (key `p_<UserId>`) holds "card seen" and "guided fight done".
  - Each allows at most one write per player every 6 s.
  - Unpublished places just keep them for the session.

## 3. Heroes and kits (R66, read from its own Rules)

The action bar is numbered **1, 2, 3... left to right**, with no gaps. A hero only gets the slots it has, in this fixed order: Combo, Heavy, Skill 1, Skill 2, Super, Dodge, Fly, Interrupt, Defensive, Skill 3. Supers are off for every hero (the R16 decision).

### Solarion (115 HP, speed 16, flies, ceiling 60)
1. Sun Jab combo
2. Solar Hammer: a cast that ramps 1 to 8 s and fires 3 pulses
3. Pounce
4. Fly
5. Solar Shield: absorbs 30, 14 s cooldown
6. Solar Absorb: a sphere

He has no Dodge. His throw is Throw.

### Wraithstep (100 HP, speed 20, regenerates 1.5 HP/s after 3 s untouched)
1. Shade Slash combo
2. Grave Scythe: leaves a Soul Drain, 2 damage every 0.5 s for 3 s
3. Grapple: shadow bats; it hits grounded targets for 2 s
4. Phase: 8 s, with glitches at 2 s and 5 s. While phased he fires lock-on Shade Bolts that stack to 3
5. Vanish: 6 s
6. Shadow Circle: radius 10, 1.5x damage inside, with a burn

He has Sneak (+25% on the first hit out of hiding).

### Tempest (105 HP, speed 18, flies, ceiling 50)
1. Spark Jab combo: 7/7/10
2. Storm Fist: 14 damage, range 22
3. Lightning
4. Lightning Snare: a root with its own DR group
5. Fly
6. Tailwind: a blink, and her stun breaker
7. Whirlwind: a lock-on cyclone with a ramping cooldown. A defensive halves it. It leaves a mist cloud with 50% damage reduction for 12 s

Lightning ticks do 3 damage and heal stacks build up.

### Bulwark (135 HP, speed 13, scale 1.18, tank)
1. Titan Cleave
2. Earth Slam: a holy circle with a fixed 0.8 s stun
3. Charge: armoured, splats into walls, leaps at flyers
4. Shield Throw: his interrupt
5. Shield Parry: a 1 s window. A landed parry reflects the blow at full damage, gives a shield and heals. Its cooldown resets to 6 s on a landed parry
6. Dimension Door: a teleport slam

He has no combo (removed in R64l), so on phones Titan Cleave takes the big ATTACK button (`Sig.attackId`). His throw is Titan Drop. Juggernaut stacks build on unblocked hits (max 5).

### Shared systems
- Fury (100 max, 50 at the start) and a 45-tick GCD.
- Stun diminishing returns (`Rules.StunDR`), with separate groups for Root (Snare) and Cyclone (Whirlwind).
- The 3rd unblocked hit in a chain knocks the victim down.
- Cast bars. Any hit stops a cast.
- Rounds are best of 3, 99 s each, then overtime with no flying.
- Nobody has a separate interrupt key except Bulwark's Shield Throw.

### Balance history
- R52 sim: Bulwark 72%, Wraithstep 68%, Solarion 56%, Tempest 5%.
- R53 to R59 applied the R52 fix package, which projected 59/52/47/43.
- R62 raised Bulwark to 135 HP.

## 4. Controls and UI rules Peter has set

**Desktop:**
- WoW-style, number-key action bar, every key rebindable (K opens Keybinds), with reset to defaults.
- Tab targets, and a click selects a target.
- R starts or restarts a fight, and P pauses.
- Never hard-code a key for a new ability. Add it to `ACTIONS` in the client and let the sequential numbering place it.

**Walking (R65d/e, keep as is):**
- Default WASD and the arrow keys go through Roblox's own PlayerModule.
- Only Q/E strafe and any rebound walk keys go through `BindToRenderStep("HW_Walk")` → `Player:Move`.
- Strafe and backpedal keep the fighter facing ahead, and `Sig.strafe` gives a procedural leg-turn pose.
- Peter reported "toons not moving" on R65 until this was fixed. Don't route the default keys through custom code again.

**Screen layout:**
- Never put clickable buttons near the action bar, or in the centre of the screen.
- Menu buttons go in the top-right **MENU** drop-down, level with the Roblox button. It's in its own ScreenGui, `HeroWarsTop`, with IgnoreGuiInset on.
- Notices sit on the left and fade. The round line is at the top left.

**Phones:**
- Every action button sits along the bottom.
- The default is one flat row: ATTACK 88, everything else 70. A "Buttons: FLAT / Styled" toggle is in MENU.
- The nearest foe is targeted automatically.
- There's no Keybinds tile, and no fly UP/DOWN buttons.
- The menu is a 3-across grid of tiles.
- Roblox scripts can't tell Android from iOS. The layout uses the safe-area inset instead.

**Looks:**
- Fixed heroes, with cosmetic-only skins.
- Gear will be sidegrades (not started).
- Never sell gameplay power, and never sell catalog items made by others.
- Solarion has no face covering. Avoid Rthro bundles.

## 5. Build and check method

Claude's builds swap the edited script sources into the previous place file. On Windows you can do the same with Python. Your R16 used `build_r16.ps1`, which isn't in the project files, so use the steps below.

1. Copy `r66/` to `r67/` and edit `r67/src/*.luau`. Bump the version strings in the client: `"HEROWARS R66 • loading character…"` and `"R66 • %s • HP"`.
2. **Swap sources into the .rbxlx by class + referent:** LocalScript `10`, Script `7`, ModuleScript `3`, ModuleScript `6`, and the named ones.
   - Never match on the first referent you find. R59/R60 had duplicate referents that clashed with the scripts, and `add_temples.py` now prefixes all of its referents.
   - `r66/apply66.py` shows the patch style used, with anchored string replacements and asserts.
3. Run the asset steps, as every build does. They're in `../HeroWars-assets/mixamo-tools/`:
   - `add_temples.py`, which bakes in Peter's Toolbox temples. It's required, or Jungle Temples loses its centre pyramid.
   - The R line currently has no Bodies or Avatars folders. Leave it that way unless Peter asks: `add_bodies.py` and `add_avatars.py` belong to the old v-line.
   - `add_rigs.py` runs only once Peter sends `HeroWarsRigs.rbxmx`.
4. Make sure Lighting has `<token name="Technology">4</token>`. Without it, Studio shows a blocking migration dialog and then a save prompt.
5. **Compile check, at Studio's own settings.** Treat any stderr output as a failure:
   ```
   luau-compile --binary -O2 -g2 <file> > NUL
   ```
   - Don't use `--null -O1`. It missed R64's "Out of local registers ... exceeded limit 200", which stopped the whole client from starting in Studio.
6. **Analyze check.** Compile alone passed R65d, which had a nil global `binds` that broke all walking. Run:
   ```
   luau-analyze HeroWarsClient__10.luau | findstr /C:"Unknown global"
   luau-analyze Main__7.luau | findstr /C:"Unknown global"
   ```
   - Anything other than Roblox's own globals is a bug: `game`, `workspace`, `script`, `task`, `warn`, `Enum`, `Instance`, `Vector2`, `Vector3`, `CFrame`, `Color3`, `UDim`, `UDim2`, `TweenInfo`, `NumberRange`, `NumberSequence`, `NumberSequenceKeypoint`, `ColorSequence`, `RaycastParams` and `Random`.
7. **Place checks:**
   - Every referent is unique. R66 has 1111/1111.
   - Temples are present, and Technology is 4.
8. Write `r67/R67_NOTES.md`. Say what changed, in Peter's words where possible, plus the checks and what hasn't been tested. Add one line to `PLAYTEST.md`.

**The 200-local rule:** the client's main chunk has no free locals.
- Wrap every new feature in `;(function() ... end)()` and share across blocks through `Sig`.
- The same goes for Main if you add much there.
- Don't declare a local and then read it from a function defined earlier. That's exactly how the R65d `binds` crash happened.

The Luau CLI tools (luau, luau-compile and luau-analyze) come from the luau-lang/luau GitHub releases.

**Testing:**
- Multiplayer: Studio Test > Clients and Servers, with 3-4 clients.
- Phone view: Test > Device, then pick a phone.
- Peter plays on PC and on a Samsung A35. He has a second Roblox account for tests.

## 10. Merge R66-ui8 into your R71 (added 2026-10-12)

**What R66-ui adds** (full detail per round in `r66ui/R66ui_NOTES.md`):

| Script | Class / referent | R66-ui8 source | Diff against R66 |
|---|---|---|---|
| HeroWarsClient | LocalScript `10` | `r66ui/src/HeroWarsClient__10.luau` | `r66ui/patch/R66_to_R66ui8_HeroWarsClient__10.diff` (19 hunks) |
| Main | Script `7` | `r66ui/src/Main__7.luau` | `r66ui/patch/R66_to_R66ui8_Main__7.diff` (17 hunks) |

**How to merge:**
1. Start from your R71 place, in a new `r72/` folder. Name the build **R72**.
2. Apply the two diffs to your R71 sources. Use `git apply --3way` or `patch -p1 --merge`, or apply hunk by hunk. Every R66-ui edit is tagged `R66-ui`, `R66-ui2` ... `R66-ui8` in a comment, so you can grep for them.
   - For Main, `r66ui/patch/main_r2.py <path to Main.luau>` re-applies the ui2 server changes and asserts every anchor, so a mismatch fails loudly.
   - `r66ui/patch/client_r2.py` does the same for the ui2 client changes. ui3-ui8 client edits are only in the diff.
3. Where your R67-R71 changed the same lines, keep your behaviour and re-add the R66-ui lines around it. Likely clash points: the `remote.OnClientEvent` handler's first line, the MENU / MenuShell code, the welcome screen and lobby auto-open (R66-ui removes them), `spawnFighter` (R66-ui adds a `ring` argument and `isDummy=="practice"`), and the server `OnServerEvent` handler (R66-ui wraps it as `onServerEvent(player,action,data,seq,data_vote)` for votes).
4. The client main chunk is at the 200-local limit. R66-ui puts all its new code in `;(function() ... end)()` blocks or table fields (`Sig.*`, `D.*`); keep it that way.
5. Swap the merged sources into the place by class + referent (`r66ui/swap.py base.rbxlx out.rbxlx`, edit its JOBS list and `src` path). Never match on the first script name.
6. Run the checks in section 5: `luau-compile --binary -O2 -g2` on every script with nothing on stderr, luau-analyze with no unknown globals except Roblox ones, unique referents, Technology 4, XML parses.
7. Update the version strings (`R66-ui8` appears in the client's loading/HP labels) to R72.

**Test before Peter publishes:** solo against the bot, then Test > Clients and Servers with 2-3 players (votes, practice dummies, duels), then Test > Device on a phone size (MENU tiles, card, Simple looks). DataStore saving only works in the published game.
